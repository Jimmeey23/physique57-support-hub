# Physique 57 India — Support & Ticket Hub
## Table B · Intake field plan (field ID · type · required · conditional · routing · SLA)

*Built 20 Sep 2026. 23 universal fields applied to all 296 sub-categories, plus 3129 sub-category-specific field rows (10.6 avg per sub-category), 180 distinct field IDs.*

## How to read this
- **The form = universal block + the sub-category block.** Every ticket first collects the 23 fields below, then the fields for its own sub-category. That keeps the taxonomy honest without making 296 bespoke forms.
- **`Field type`** uses the hub's own `StructuredField` union (`text`, `textarea`, `number`, `datetime-local`, `select`, `rating`, `multiselect`) — plus 3 types that **do not exist in `ticket-contract.ts` yet** and need adding: `radio`, `file`, `url`.
- **`Is conditional` + `Linked field ID`** are the same mechanism as `dependsOn`/`dependsOnValue` already in `StructuredField`; a conditional field is hidden until its linked field takes the stated value.
- **Options are real constants**, not invented: studios, rooms, 24 class formats, 20 trainers, 45 membership SKUs, 12 systems, 30 equipment types are pulled from `constants.ts` at build time.
- **Owner / escalation / SLA / priority repeat on every row** because routing and SLA change *inside* a category (e.g. `Music System Too Loud/Low` sits under Repair & Maintenance but routes to Training).
